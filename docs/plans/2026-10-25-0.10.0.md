# 0.10.0 plan (2026-10-25)

The owner's decisions from the planning session, and the brief every lane
works from. One release, polish and fixes, no new big features except the
light mixing the owner asked for. Quality is never traded for efficiency.

## Ground rules for every lane

- Read [AGENTS.md](../../AGENTS.md) first. Its Never list holds. Do not edit
  AGENTS.md.
- Start from the tip of `work/next-release`. Run `git log -1` and say which
  commit you started from.
- Commits follow `area: what changed in plain words`, small and focused.
- Do not edit `CHANGELOG.md` or the What's New catalog. Report your bullets.
- Swift tests must never put a real window on the owner's screen. Until the
  test-window guard lands, run only the Swift suites you need.
- Prove behaviour with tests on synthetic data. Visible work gets render
  proofs that you open and look at.
- Nothing new leaves the Mac without an opt-in that defaults off, and a test
  proves it stays off.
- Finish with: commits made, tests run and their results, what you could
  not prove, and anything another lane must know.

## Decisions

### Lights

1. A provider animation the person chose always plays for that provider.
   The turn-length ember only plays for providers left on Automatic.
2. Ambient cues (ember, celebration, milestones) become short layers on top
   of the running animation, a few seconds at most, never a long takeover.
3. Fix the ember freeze: renewal is deduplicated by the write layer
   (`_status_bar_production.py` omits `ambient.dedupe_token`), and finite
   programs hold their last frame when they end.
4. Fix reassert trimming (`led_status.py` ~1510): only explicitly marked
   approach frames are dropped. Breathing keeps both halves.
5. One provider (or one agent group) running: that provider's animation.
   Two or more different providers running: the global Mix chosen in Studio.
   - Share mixes (Split, One at a Time, Everyone) give each provider a share
     that plays the provider's own animation with its Studio parameters.
   - Mix animations are built for several colours: Alternate, Relay, Weave,
     Tide to start. Each has Studio parameters like any animation.
   - Smooth and Status Only stay for a calm strip; Status Only says it shows
     no animation.
   - An ask always wins over any mix.
   - When a combination cannot play exactly, Studio says what plays instead.
     No silent fallbacks. A test grid covers every mix x animation x cue.
6. Agent groups. Related sessions count as one agent on the strip and in the
   panel, shown as the root agent in its provider's colour. A group row
   expands to its members. Asks stay individual.
   - Links come only from explicit evidence: T3 Code lineage
     (`~/.t3/userdata/statev2.sqlite`, native thread bindings), Claude hook
     `session_id`/`agent_id`, Codex `parent_thread_id`, Factory session
     headers `callingSessionId`, Devin `subagent_heads`, Cursor, Hermes,
     OpenCode, OpenClaw, Gemini and Grok parent fields.
   - Devin sub-agents join their Devin parent session. If the parent is
     unknown and exactly one Devin session runs, they join it.
   - A worker with no provable parent is a dim "unlinked worker" with no
     share of the strip unless it asks. It is logged so the gap can be fixed.
   - Never infer a group from a shared folder or process ancestry. Reject
     cycles, ambiguous bindings and stale evidence.
   - Required fixture: a T3 thread spawns Factory, Claude and Codex
     children, each spawns a native sub-agent; all seven resolve to one group.
7. Studio is the home of everything about light: provider animations and
   colours, mixes and blend modes, cues, state colours, speed, scenes,
   celebrations. Device overrides show in Studio as labelled rows. Settings
   Devices keeps only hardware: connect, firmware, brightness, direction,
   Screen Bar placement.

### Usage and providers

1. Claude usage stays live after Claude Code renews its sign-in. Read
   `Claude Code-credentials` through `/usr/bin/security` (it stays trusted
   when Claude Code rewrites the item), with a timeout, off the daemon's
   main loop. Add a CLI fallback (`claude` `/usage`) behind an opt-in that
   defaults off. Never refresh or write Claude Code's token. When it fails,
   name the cause ("Keychain access lost after Claude renewed its sign-in").
   A test fakes a Keychain item rewrite and proves Claude stays live.
2. Provider states:
   - installed, quota source not running: last reading's age plus
     "Open <app> to refresh" with a button;
   - installed but failing: visible with the cause, the fix and the age of
     the last good reading;
   - a quota window that reset since the last reading never shows the old
     percentage as current;
   - never set up and not installed: not in the panel, still in Settings;
   - used before, now gone: stale for a week, then one line "not found on
     this Mac" with a Hide button. Nothing hides itself.
3. Antigravity: its quota service only runs while the app is open. Fix the
   "not detected" classification, offer Open Antigravity, and add `agy` CLI
   service support with the same identity checks. Fix single-location
   detection elsewhere (Cursor, OpenCode, Gemini only in `/Applications`;
   OpenClaw config path; fixed credential paths).
4. One provider list is the single source of truth. Per provider: Track
   (collect at all; off is truly off), Menu bar, Panel, and one shared
   order set by dragging. Editable in Settings and in place from the panel.
   The owner's current menu bar meter icon stays as it is.
5. Token history: stays on, keeps hour/day/model totals up to date instead
   of rebuilding them, one shared cache for the card, History and Overview,
   and a switch that truly stops it.

### Efficiency (path 1)

Measured on build 3299 with three agents: app 7-8% CPU, 450-750 MB and
growing; daemon 7% CPU, about 500 MB. Budgets, checked by a 24 hour run on
the owner's Mac: daemon under 150 MB and under 1% CPU; app under 250 MB,
flat over 24 hours, under 1% CPU; no daemon stall over 250 ms.

- Screen Bar: no 60 Hz main-thread redraw. Play precomputed keyframes,
  colours made in the layer's colour space. Same look.
- Daemon: remove the AppKit/PyObjC legacy controller from the headless
  daemon; libproc instead of forking `ps`; event-driven settings and process
  watchers with recovery scans; a persistent `codex app-server` if it pays;
  transcript caches bounded by bytes; Keychain reads off the main loop.
- Protocol: publish only the slices that changed, with a generation per
  slice. LED write stats leave the full state. The app stops replacing its
  whole model on every message.
- App memory: find and stop the observation registrations that pile up.
- Lid sensor slows down when the lid is far from its arming angle. The menu
  bar listing becomes event-driven with a long calm interval.
- Later: a Swift trial of transcript indexing. A port decision goes to the
  owner with measured numbers.

### Off means off

Every optional feature declares what it starts: windows, timers, display
links, observers, daemon jobs. Off tears all of it down. A test switches
each feature off and fails if anything is still running. Known leaks:
aquarium observation, disabled providers' jobs, disabled cue planners,
island and Screen Bar windows, notch announcement watchers and Bluetooth,
remote peers timer, Fold overlay, daemon lid probe, presence sensors, a
master off per LED device.

### Reliability and latency

- Trace the 2.1 GB in 7.5 h of daemon writes (Oct 21) to a file before
  changing anything.
- Log the view behind AppKit's negative-size layout faults.
- Routine successes (LED writes, linked-write timing, display changes) go to
  debug level.
- Leftovers from the archived 2026-10-22 plan (tag
  `archive/stash-upgrade-plan-2026-10-22`): refill detection misses resets
  when use resumes right after (95 -> 100 -> 99); event gaps in Usage Center
  and confetti queues; refused setting writes only log; Fold compiles its
  shader under a lock; standalone `--allow-answers` and Stream Deck setup
  skip answering consent.
- Asks interrupt ordinary notch notices. Asks and lifecycle changes skip the
  250 ms refresh coalescing. The Screen Bar shows a new state at once while
  its animation compiles.

### Design (mockups first, then build)

Opus mockups, rendered for the owner before any UI is built: Settings
reorganized on native macOS 26 patterns; Studio as the home of light with
mix-animation previews; a clean Devices page; the provider list with drag,
logos and columns, editable from the panel; panel cleanup; a Studio button
on the panel and a keyboard shortcut; an Alcove-quality notch; a Usage
Center chart in the style of T3 Code's (axes on 1/2/5 steps, crosshair,
honest scanning/stale/empty states); What's New and Setup; a motion
comparison. Motion is Raycast-snappy: content on the first frame, entrances
around 120-150 ms. Design tokens for type, colour, radius and motion, with a
`make fast` check that rejects one-off sizes and colours.

### Mockup review (owner approved, 2026-10-25)

The approved mockups are in `2026-10-25-0.10.0-mockups/` next to this file
(open `index.html`). The owner approved all of them with two changes:

1. T3 Code is not a provider. It is a way of running the providers. It
   leaves the provider list and lives under an Integrations (compatibility)
   section. It is always on and detects by itself whether T3 Code is in use,
   at no cost when it isn't (read its data only while T3 Code runs, and only
   when its files change).
2. The notch keeps its current look and shelf. No fundamental redesign. Small
   cleanup only: the working-agents part matches the rest of the new UI,
   design tokens and type sizes apply, groups show like the panel. The
   notch mockup is a reference for that cleanup, not a redesign to build.

Defaults the owner accepted:

- Panel: bars show percent used; reset times in small text under each bar;
  usage moves to the top when no agents run; finished sessions stay 10
  minutes then fold into Earlier; hiding from the panel does not turn off
  Track.
- Settings: Notch & Shelf and Privacy are their own pages; Track off stops
  JR-Bar's work but leaves the hook, and a separate "Remove integration"
  button removes it; Studio is its own window.
- Studio: in Split the extra LED goes to the agent that needs the person
  most, then the one that started first; One at a Time holds 4 s; "play on
  devices" is on by default; mix names Alternate, Relay, Weave, Tide.
- Notch: opens on hover after 150 ms and on click; the finished notice only
  for turns over 2 minutes; Macs without a notch get a small top-centre
  pill; shelf files survive a restart as references; return answers the ask
  on screen and Tab moves to the next.
- Usage Center: reopens on the last provider; cost shows, marked as an
  estimate, and can be turned off; cache reads start hidden; the 30-day chart
  replaces the block heatmap; context shows open sessions only.
- What's New leads with Mix and quotes measured CPU and memory once the
  24-hour run proves them. A newly installed provider gets a small "New
  provider found" card, not Setup again.
- Motion: panel 140 ms, notch 250 ms, no bounce. 11 pt minimum everywhere;
  closed notch wings use icons and numbers. Accent follows the system
  accent; provider colours stay fixed and are editable in Studio.
- Shortcuts: option-command-J opens the panel, option-command-L opens
  Studio.
