### Recoverable archive cleanup

Build 22 includes Archive Trash. Move to Archive Trash removes a record from
Saved while retaining its object and metadata. Restore checks the object's hash
and restores the exact record. Empty Archive Trash requires a separate native
confirmation and deletes only the IDs reviewed by that confirmation, including
entries hidden by search. Cancel preserves them. Original source files remain
untouched. Empty-trash and restore actions disable when no trashed entries exist.

Catalog v2 adds a removal table and upgrades valid v1 catalogs transactionally.
Removal IDs remain after restore or permanent deletion so legacy reconciliation
cannot resurrect deleted entries or overwrite restored intent. A stale purge
request skips records already restored or reimported. Each permanent removal
holds the catalog writer lock; remaining entries survive failures for retry.
Import rollback also checks trashed references before removing an object that
another importer may have adopted. Independent read-only reviews found no
remaining concrete data-loss issue in those paths.

Full exports retain Saved and Archive Trash separately in a v2 manifest when
trash exists. Exports without trash retain v1 format. Reopening a snapshot
preserves its saved/trash distinction. The original legacy manifest is preserved.
A private pre-migration backup contains the v1 catalog, both verified objects,
and the legacy manifest at
`.jrbar-verification/goal-20260919-21/archive-before-migration/`.
Older app builds reject the v2 catalog; that backup is available if a rollback
needs the previous catalog format.

exact restoration, content integrity, cancelled purge, legacy resurrection,
